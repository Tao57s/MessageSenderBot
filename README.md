# MessageSenderBot

Мультиплатформенный бот для пересылки сообщений из Telegram, Max и VK в активные чаты. Доступ к отправке сообщений предоставляется только пользователям из белого списка, а управление пользователями и чатами выполняет администратор.

## Возможности

- запуск Telegram-, Max- и VK-ботов из одного файла;
- пересылка сообщений во все активные чаты выбранной платформы;
- общий список разрешённых пользователей;
- добавление, удаление и включение/выключение чатов;
- хранение пользователей и чатов в PostgreSQL;
- настройка платформ и секретов через `.env`;
- запись событий в `bot_system.log`.

## Используемые технологии

- Python 3.12+;
- PostgreSQL;
- SQLAlchemy и asyncpg;
- aiogram для Telegram;
- maxapi для Max;
- vk-api для VK.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `Run.py` | Единая точка запуска всех включённых ботов |
| `TelegramBot.py` | Telegram-бот и его обработчики |
| `MaxBot.py` | Max-бот и его обработчики |
| `VkBot.py` | VK-бот и обработчики VK Long Poll |
| `database.py` | Модели и операции с PostgreSQL |
| `init.sql` | SQL-структура таблиц и индексов |
| `.env.example` | Пример конфигурации |
| `requirements.txt` | Зависимости проекта |

## Требования

- Python 3.12 или новее;
- PostgreSQL 12 или новее;
- токены ботов нужных платформ;
- права администратора для добавления ботов в группы и чаты.

## Установка

1. Клонируйте репозиторий и перейдите в каталог проекта:

   ```bash
   git clone https://github.com/Tao57s/MessageSenderBot.git
   cd MessageSenderBot
   ```

2. Создайте виртуальное окружение:

   ```bash
   python -m venv venv
   ```

   Активация в Windows PowerShell:

   ```powershell
   .\venv\Scripts\Activate.ps1
   ```

   Активация в Linux/macOS:

   ```bash
   source venv/bin/activate
   ```

3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Создайте базу данных PostgreSQL, например `bot_db`.

5. Скопируйте `.env.example` в `.env` и заполните значения:

   ```powershell
   Copy-Item .env.example .env
   ```

   В Linux/macOS:

   ```bash
   cp .env.example .env
   ```

6. При необходимости примените SQL-скрипт `init.sql`. При запуске приложения таблицы также создаются автоматически через SQLAlchemy.

## Деплой через Docker

На сервере должны быть установлены Docker Engine и Docker Compose v2.

1. Получите код проекта на сервере и перейдите в его каталог:

   ```bash
   git clone <URL_РЕПОЗИТОРИЯ> MessageSenderBot
   cd MessageSenderBot
   ```

2. Создайте рабочий файл конфигурации и обязательно замените пароли и токены:

   ```bash
   cp .env.example .env
   nano .env
   ```

   Для Docker оставьте `DATABASE_URL` в таком формате:
   `postgresql+asyncpg://bot_user:ПАРОЛЬ@db:5432/bot_db`.
   Значение `POSTGRES_PASSWORD` должно совпадать с паролем в `DATABASE_URL`.

3. Соберите образ и запустите приложение вместе с PostgreSQL:

   ```bash
   docker compose up -d --build
   ```

4. Проверьте состояние и логи:

   ```bash
   docker compose ps
   docker compose logs -f app
   ```

5. После изменения кода обновите приложение:

   ```bash
   git pull
   docker compose up -d --build
   ```

Остановить контейнеры можно командой `docker compose down`. Данные PostgreSQL сохраняются в Docker volume и не удаляются этой командой. Не используйте `docker compose down -v`, если база данных нужна.

Рабочий `.env` не добавляйте в Git. База данных доступна только внутри Docker-сети и не публикуется на внешний порт.

## Конфигурация

Основные переменные в `.env`:

| Переменная | Описание |
| --- | --- |
| `DATABASE_URL` | URL подключения к PostgreSQL, например `postgresql+asyncpg://user:password@localhost:5432/bot_db` |
| `ENABLE_TELEGRAM_BOT` | Запуск Telegram-бота: `true` или `false` |
| `ENABLE_MAX_BOT` | Запуск Max-бота: `true` или `false` |
| `ENABLE_VK_BOT` | Запуск VK-бота: `true` или `false` |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота от BotFather |
| `ADMIN_TELEGRAM_ID` | ID администратора в Telegram |
| `PROXY_URL` | Необязательный SOCKS-прокси для Telegram |
| `MAX_BOT_TOKEN` | Токен Max-бота |
| `ADMIN_MAX_ID` | ID администратора в Max |
| `MAX_API_URL` | URL API Max, если используется нестандартный адрес |
| `VK_GROUP_TOKEN` | Токен группы VK |
| `ADMIN_VK_ID` | ID администратора в VK |
| `VK_API_VERSION` | Версия API VK |
| `VK_GROUP_ID` | ID группы VK |

Секретные токены и рабочий `.env` нельзя публиковать в репозитории. Для других разработчиков используйте `.env.example` с тестовыми или пустыми значениями.

## Запуск

После настройки окружения выполните:

```bash
python Run.py
```

При запуске приложение инициализирует базу данных, регистрирует включённые платформы и запускает их обработчики. Логи выводятся в консоль и сохраняются в `bot_system.log`.

Отключить ненужную платформу можно в `.env`, например:

```dotenv
ENABLE_TELEGRAM_BOT=true
ENABLE_MAX_BOT=false
ENABLE_VK_BOT=true
```

## Команды администратора

Команды доступны администратору соответствующей платформы. Идентификаторы пользователей и чатов должны быть числовыми.

| Команда | Назначение |
| --- | --- |
| `/start` | Проверить доступ и показать справку |
| `/add_user <ID>` | Добавить пользователя в белый список |
| `/remove_user <ID>` | Удалить пользователя из белого списка |
| `/list_users` | Показать разрешённых пользователей |
| `/add_chat <ID> [название]` | Добавить чат для пересылки |
| `/remove_chat <ID>` | Удалить чат |
| `/toggle_chat <ID>` | Включить или выключить пересылку в чат |
| `/list_chats` | Показать список чатов |

Для Max также предусмотрена команда `/getid` для получения ID чата.

Пример добавления Telegram-чата:

```text
/add_chat -1001234567890 Рабочая группа
```

После добавления пользователя в белый список он может отправлять сообщения боту. Сообщения пересылаются в активные чаты, зарегистрированные для соответствующей платформы.

## База данных

Используются таблицы:

- `allowed_users` — идентификаторы разрешённых пользователей Telegram, Max и VK;
- `forward_chats` — идентификаторы чатов, их названия и статус пересылки.

Для одной записи можно сохранить соответствующие идентификаторы пользователя или чата на разных платформах.

## Логи и отладка

Основной лог записывается в файл `bot_system.log`. Для диагностики проверьте:

1. корректность значений в `.env`;
2. доступность PostgreSQL;
3. права ботов в целевых чатах;
4. правильность ID администратора, пользователей и чатов;
5. сообщения в консоли и `bot_system.log`.

## Безопасность

- не добавляйте `.env` в Git;
- не используйте реальные токены в `.env.example`;
- выдавайте права администратора только доверенным пользователям;
- при публикации токена немедленно отзовите его и создайте новый.
